# Toast

Simple notifications use Frame singleLine by default. Rich notifications retain their multiline body layout instead of forcing the entire notification onto one line.

<a id="组件介绍"></a>

## Overview

Show brief feedback for actions or status changes, with optional icons, actions, and rich content for success, errors, or reminders.

<a id="使用选择"></a>

## When to use it

Use Toast for short-lived action feedback through Toaster. Keep notification history and activity feeds in persistent content lists.

- Call `toast()` to enqueue feedback; Toaster manages the queue. When rendering Toast independently, the page removes it after close.
- `as="toast"` binds to a host click trigger. Leading/trailing roles add content; `parts` configures only generated controls. Use inherited `singleLine` with `Text lines={1}` for short labels. Internal content gaps stay at least 4 CSS px; rich multiline content retains its layout.

<a id="快速开始"></a>

## Quick start

This example shows the recommended basic composition. See the sections below for more cases and composition limits.

```svelte
<script lang="ts">
	import { Toast, Button, Text } from '@snowui-design-system/components';
</script>

<div style="display: flex; flex-direction: column; align-items: center; gap: var(--gap-4); max-width: 100%;">
	<Toast singleLine><Text lines={1}>Draft saved</Text></Toast>
	<Toast positive singleLine><Text lines={1}>Changes published</Text></Toast>
	<Toast positive={false} singleLine><Text lines={1}>Connection lost</Text></Toast>
</div>
```

| Keyword | Type | Default | Description |
| --- | --- | --- | --- |

## Usage boundaries and details

<a id="toaster-内置组件双模式"></a>

<a id="toaster-内置组件双模式-1"></a>

### Configuring Toast generated by Toaster

- `Toaster.parts.Toast` configures generated Toasts. `Toaster.parts.Text` configures only labels generated from text strings; it does not configure custom children.
- Toaster owns queue state, position, and dismissal events. Explicit Toast Props override part settings.

SnowUI notification delivery has three public pieces:

| Piece | Role |
| --- | --- |
| `<Toast />` | Single Toast visual shell with three slots; usable standalone or within Toaster. |
| `<Toaster />` | Global Portal container subscribed to the queue. Mount once per application; it renders stacks at six positions. |
| `toast(...)` | Command entry callable from `.ts` or `.svelte`. |

Standalone panel Toast explicitly uses `GENERIC_SCALE_APPEAR_MOTION` for opacity and scale at the former Frame timing instead of inheriting `whileAppear={true}` fallback. Queued Toaster still uses its position-specific slide, opacity, and scale combination; both appearances are retained.

<a id="功能概览"></a>

<a id="功能概览-1"></a>

### Feature overview

- Six positions: `top`, `top-left`, `top-right`, `bottom`, `bottom-left`, and `bottom-right`, 16px from the viewport edge; default `top`.
- Leading/Content/Trailing slots; generated icons can be replaced externally.
- Default variant is a dark pill with `blur(var(--size-10))` backdrop blur. Rich variant is a Background/3 glass card using `.snowui-quick-action-panel` blur.
- Automatically dismiss after six seconds by default; `duration: 0` persists.
- Hover pauses the dismissal timer; leaving resumes its remaining duration.
- Toast stacks automatically at each position. Defaults: `gap=8`, `maxVisible=3`, `scaleStep=0.05`, `stackOpacityStep=0.2`; width hugs content. These settings are configurable.
- One Toast root combines entry, exit, stack shifts, and pushed-out last layer. Lifecycle motion uses `transform` and opacity; stack shifts and scale use independent CSS `translate`/`scale`. Stack opacity multiplies Frame fade. On close, play Disappear before removing the queue entry.

<a id="布局模型"></a>

<a id="布局模型-1"></a>

### Layout model

Main layout model: **composite management layout**.

- Toaster mounts a page-level Portal on `<body>` with six absolutely positioned stack regions. Each slot is an absolute Frame using `currentState="Appear" | "Disappear"` for lifecycle motion.
- HeroUI-style stack indexing sets CSS `translate` and `z-index`: index 0 is frontmost, and deeper items shift inward.
- Only the frontmost Toast is interactive. Deeper layers keep real content but differ by position, scale, and opacity.
- An individual Toast uses a `Frame row` slot-host layout with Leading, Content, and Trailing.
- The rich variant’s close X is an absolute top-right decoration, outside the three slots.
- The outer wrapper of the close X is an always-interactive transparent hit host (at least 16x16, matching the Sidebar collapse button): hovering the Toast body or pointing directly at the X position (including the portion extending beyond the Toast corner radius) reveals X with a minimum 16x16 hit and click area; non-frontmost and exiting Toasts do not respond.
- When triggering the same notice repeatedly, call `toast()` again to stack a new item above the existing one instead of calling `dismissToast` before recreating it, avoiding a jarring reappear flicker.

<a id="toastinput-命令式入口"></a>

### `toast(input)` command API

```ts
import { toast } from "@snowui-design-system/components";

toast("Done");                                        // String shorthand -> equivalent to { text: "Done" }
toast({ text: "Done", positive: true });              // Positive -> green CheckCircle
toast({ text: "Something Wrong", positive: false });  // Warning / negative -> yellow Warning
toast({ text: "Plain Notice" });                      // Omit positive -> hide built-in status icon
const id = toast({ text: "Persistent notice", duration: 0 });
dismissToast(id);                                     // Dismiss manually
showToast("saved-template");                          // Trigger <Toast template id="saved-template">
```

| Parameter | Type | Default | Description |
| --- | --- | --- | --- |
| `positive` | `boolean` | — | `true` shows positive CheckCircle; `false` shows warning icon; omitted shows no generated icon. |
| `text` | `string` | — | Imperative shorthand text. Toaster renders Text with default one-line truncation and a full-text tooltip. |
| `children` | `Snippet` | — | Custom body content takes precedence over `text`. |
| `leading` | `Snippet` | — | Custom Leading Snippet. |
| `trailing` | `Snippet` | — | Custom Trailing Snippet, often a Button in rich variant. |
| `variant` | `"default" \| "rich"` | `"default"` | Visual variant. |
| `size` | `"sm" \| "md"` | `"md"` | Applies to default variant only; rich uses fixed `md`. |
| `position` | `ToastPosition` | `"top"` | One of six display positions. |
| `duration` | `number` | `6000` | Duration in ms; `0` persists. |
| `onDismiss` | `() => void` | — | Dismissal callback. |

Related functions:

- `dismissToast(id: string): void` closes one Toast.
- `dismissAllToasts(position?: ToastPosition): void` closes all Toasts or those at one position.
- `showToast(id: string, overrides?: ToastOptions): string | undefined` triggers a registered `<Toast template id="...">`; overrides may change position, duration, and other runtime options.

<a id="动效要点"></a>

### Motion behavior

Motion uses one Toast root:

- Lifecycle `whileAppear`/`whileDisappear` controls root `transform` and `--su-motion-opacity`. Stack shifts and scale use independent CSS `translate`/`scale`, so they do not overwrite the lifecycle transform.
- Stack opacity multiplies lifecycle fade. Layers two and three default to 0.8 and 0.6; exiting reduces the current opacity by 20%.
- Extra offscreen exit distance merges into `--snowui-toast-stack-translate-y` alongside lifecycle percentage motion, so deep layers can leave the viewport.
- Background, shadow, and `backdrop-filter` stay on the same root; there is no separate blur plate.
- `maxVisible` limits visible layers, not queued entries. The old last layer enters `pushed-out` when a new Toast arrives.
- Hovering any visible Toast at a position pauses the whole group’s dismissal timers. Only the front `idle` layer reveals the close X on Toast or X hit-area hover; deeper layers do not.

<a id="toast-视觉单元"></a>

### `<Toast />` visual component

Inherits `FrameProps` except `children`, and adds:

> Since v2.0.0, `title`, `description`, and `icon` Props are removed. Pass text through children; `positive` selects the generated icon, with no icon when omitted.

<a id="全局挂载-命令式触发"></a>

### Global mount and command trigger

```svelte
<script>
    import { Button, Frame, Text, Toast, Toaster, showToast, toast } from "@snowui-design-system/components";
</script>

<Toaster />

<Button onclick={() => toast("Done")}>Show Toast</Button>
<Button onclick={() => toast({ text: "Something Wrong", positive: false })}>
    Warning
</Button>
<Button
    onclick={() =>
        toast({
            text: "Saved",
            positive: true,
            variant: "rich",
            position: "top-right",
        })
    }
>
    Rich Toast
</Button>
```

### Standalone Toast (without `toast()`)

```svelte
<Toast positive>Done</Toast>

        <Text>Saved</Text>
        <Text class="text-12 text-black-40">Your changes are synced.</Text>
    </Frame>
</Toast>
```

<a id="内嵌模式-v110astoast"></a>

### Embedded `as="toast"` mode (v1.1.0)

An embedded Toast triggers on host click without an ID or manual `showToast`. See ComponentGuidelines §5 for floating components’ three activation modes (`docs/standards/ComponentGuidelines.md`).

```svelte
<Toaster />

<Button variant="filled">
    Save
    <Toast as="toast" positive position="top-right">Saved</Toast>
</Button>
```

<a id="声明式模板-按钮触发"></a>

### Template declaration and button trigger

```svelte
<Toaster />

<Toast id="saved-rich-toast" template class="items-start" variant="rich" positive style="width: 15rem;">
    <Frame column class="flex-1 min-w-0">
        <Text>Text</Text>
        <Text class="text-12 text-black-40">Text 2</Text>
    </Frame>
    <Button as="trailing" variant="gray">Button</Button>
</Toast>

<Button onclick={() => showToast("saved-rich-toast", { position: "top-right" })}>
    Add Rich Toast
</Button>
```
